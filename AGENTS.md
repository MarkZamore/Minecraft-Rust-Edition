# Minecraft Rust Edition

Прочитать README, integration/steam/README.md, locks, tools/overlay-receipt.json и
tools/UPDATE-ACCEPTANCE.md. На этом ПК также действуют правила LANMinecraft.

## Сохранение правок при обновлении Horizon

- Использовать точные подписанные исходники и Windows-архив из upstream-lock.
  Проверить Ed25519 в staging; плавающий nightly не является постоянным входом.
- Все обязательные слои из integration/steam/required_layers.py сохраняются при
  обновлении. Пропавший anchor, файл, проверка личности, вызов или послепроверка
  блокирует выпуск. Нельзя устранять конфликт удалением слоя, отключением
  проверки или подстановкой старой квитанции. Перенести тот же эффект на новый
  API, проверить поведение и лишь затем обновить проверяемый контракт.
- Сохранять Steam-профиль/UUID/ник/скин, проверенную привязку гостя и закрытие
  публикации, приглашения, список Steam-миров и ручные серверы. Однокнопочная
  публикация возвращает в игру; затем в том же месте меню стоят «Жалобы».
  Команды гостя наследуют Allow Commands владельца с серверной проверкой прав.
- Сохранять автономную подготовку, пресет, выключенный диктор, название/путь
  Minecraft Rust Edition и ID minecraft-9. Не возвращать nativeProject.websiteUrl.
  Не вводить собственные пределы рендера, симуляции, теней или выдачи чанков.
- Не возвращать автоматическое добавление публичных/рекомендуемых серверов.
  Ручные записи и ввод адресов сохраняются; маркер предложенных адресов не
  доказывает происхождение строки servers.dat. При авторском обновлении новый
  seeding или каталог переносится с сохранением этой политики. Обязательны
  source guard и server_list_qa.py на обычном запуске без CLI harness-флагов;
  отчёт точного payload входит в выпускной gate и не заменяется обычным smoke.
- Главный экран сетевой игры по умолчанию содержит только Steam-миры. Все
  прежние записи servers.dat доступны через явный раздел «Сохранённые серверы»;
  редактор и прямой ввод работают штатно, новый ручной сервер остаётся выбранным
  в сохранённом списке. Возврат из заголовка открывает Steam-раздел. Просмотр
  списка и статусные favicon не переписывают NBT и не удаляют старые строки.
  Выбор Steam-мира связан с его адресом, поэтому перестановка или исчезновение
  discovery-записи не может переключить Enter/Join на другой мир.
- Перед сборкой создать tools/required-layer-proof.json штатным проверяющим
  инструментом. При обновлении source/recipe/Steam pin старая квитанция не годится.
- Мост уведомлений LANMinecraft остаётся частью обязательного native UI, без
  отдельного мода, своих окон и перехвата ввода. Сохранять финальный вывод обычного
  Renderer и split Compositor, подтверждение только после настоящего present
  (также async-submit и frame generation), UTF-8 Properties, DPI один раз и
  владение session.json лаунчером. Запрет unsafe в игровом render crate не
  ослаблять: системный шрифт изолирован безопасным API локальной platform crate.
  Выпуск требует `tools/native_notices_qa.py` для точного payload и capability
  native-launcher-notices-v1; зависимый манифест публикуется только после
  подтверждённой публикации поддерживающего EXE лаунчера.
- Перед выпуском нужны отчёты точного набора файлов: запуск/сохранение/повторное
  открытие/кеш/меню и оба гостевых сценария через T/type/Enter. Изменение любого
  исполняемого файла, подготовщика, пресета или входных данных делает прежнюю
  приёмку неприменимой. Не записывать PASS вручную и не дописывать новый context
  к старому прогону. Исторический импорт разрешён только для уже принятого
  точного Git-снимка через --import-reviewed; это не новый прогон.
- --prepare-qa создаёт candidate-manifest.json только для локальной проверки
  установки. Выпускной pack-manifest.json требует успешного восстановления
  обновления и сохранности личных файлов для точного целевого инвентаря.
- Отложенная пользователем живая Steam-приёмка остаётся NOT RUN с причиной.
  Это не освобождает от проверки локальных гостей и прав команд. Не подменять
  результат реального Steam-подключения локальным TCP-прогоном.
- Архивы публикуются и независимо скачиваются с SHA-256 до манифеста. Изменения
  защиты/QA/документации сами по себе не требуют нового runtime или EXE лаунчера.

Данные продолжения, инструменты, locks и компактные отчёты хранятся в Git.
Тестовые установки/миры и сборочные результаты удаляются после фиксации отчёта.
