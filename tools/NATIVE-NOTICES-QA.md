# Нативные уведомления в точном Windows-клиенте

Запускать после сборки и staging клиента с `native-launcher-notices-v1`, квитанции
и актуального source proof. Инструмент не принимает старый EXE по одному совпадению
имени: отчёт привязан к полному `execution_context` до и после проверки.

```powershell
python tools/native_notices_qa.py --candidate $candidate --controller $controller `
    --cache $verifiedBootstrapCache --out $registeredRun/notices-qa
```

`$verifiedBootstrapCache` — действующий проверенный кеш самостоятельного bootstrap.
Не запускать одновременно другую игру с этим же кешем: bootstrap удерживает свой
штатный session lock. Игровой профиль и synthetic notice session создаются только
в новом `--out` внутри зарегистрированного `artifacts/agent-runs/<task>/RUN.json`.
Не передавать личный игровой каталог. Окно QA должно оставаться доступным: во время
проверки F11 и ввода чата не переключать его другим приложением.

Сценарий запускает настоящий bootstrap, проверяет PID фактического дочернего EXE,
его цепочку родителей и заголовок. Не подменяет Steam-профиль и не запускает другую
сборку. Пустая страница модов, `session.json` и GUI scale остаются прежними.

В `native-notices-qa.json` сохраняются:

- полный контекст payload/recipe и SHA клиента/bootstrap;
- снимки настоящего конечного кадра через unscaled `horizon-ctl screenshot`,
  измеренные прямоугольники карточек и размер реального HWND;
- свежие post-present heartbeats `native-ui-v1`, actual child PID, count 0–3,
  transformations=0 и отсутствие ошибки до и после каждой фотографии;
- проверки первого меню, трёх карточек, семисекундного срока, сохранения прежней
  карточки при оборванном UTF-8/Unicode properties до её исходного срока;
- timestamp +1500 мс: сначала нет карточки, затем она появляется;
- physical width при DPI 1 и 2, неизменные widgets/GUI scale;
- полноэкранная геометрия клиента относительно монитора, собственный мир,
  ввод `/list` через T/type/Enter при видимой карточке и меню паузы;
- продолжающий обновляться heartbeat при пустой очереди и факт уборки fixture.

PASS требует одновременно пиксельного изображения карточек и здорового свежего
heartbeat. Синтетическое создание изображений или дописывание PASS в старый
отчёт не допускается. Полный игровой прогон обязателен отдельно от проверок
вспомогательного анализатора:

```powershell
python -B -m unittest discover -s tools -p test_native_notices_qa.py -v
```

Набор screenshot PNG и компактный отчёт остаются доказательствами. Мир, настройки,
файлы с IPC token и синтетическая очередь удаляются в `finally`, свои дочерние
процессы останавливаются. Неудача сохраняет FAIL и причину, а не частичный PASS.
